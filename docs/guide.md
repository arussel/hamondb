# Hamon Guide

## Core concepts

A single `Hamon` instance holds:

| Concept        | What it is                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| **Table**      | A typed collection of rows (one Rust struct per table).                                                      |
| **Column**     | A typed handle (`Column<T, V>`) to one field of a row. Generated by the derive macro.                        |
| **Primary key**| The unique identifier for a row. One field per table.                                                        |
| **Index**      | A secondary lookup from a value → list of primary keys. Maintained automatically on insert/update/delete.    |
| **Computed column** | A column whose value is derived from other columns (same row or cross-row via `Ctx::lookup`).           |
| **Slot**       | A singleton typed value stored as a 1-row table. Reactive like any column.                                   |
| **Resource**   | An atomically-swappable `Arc<V>`. *Not* reactive — a plain config holder.                                    |
| **Listener**   | A callback `(pk, Option<&T_old>, Option<&T_new>)` fired after a row is inserted, replaced, or deleted.       |
| **Feeder**     | A long-lived worker thread spawned by `build()` that writes into the `Hamon`.                                |

The reactive engine tracks which cells (row × column) each computed column read, and
when a dependency changes it recomputes the dependents. Cross-row and cross-table
dependencies are cascaded asynchronously via an internal recompute queue.

## Defining a table with `#[derive(Table)]`

The derive macro generates three things:

1. `impl Table for YourStruct` with `type PrimaryKey = <type of the #[primary_key] field>`.
2. `pub const FIELD_NAME: Column<YourStruct, FieldType>` for every non-`#[skip]` field,
   named in `SHOUTY_SNAKE_CASE`.
3. `impl TableExtractor<YourStruct> for YourStruct` so `builder.register_table::<T>()`
   can discover indexes, computed columns, and the primary key automatically.

### Field attributes

| Attribute                   | Meaning                                                                                         |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| `#[primary_key]`            | Required on exactly one field. Determines `T::PrimaryKey`.                                      |
| `#[index]` or `#[index(NAME)]` | Maintains a secondary index on this field. `NAME` defaults to `<FIELD>_IDX`.                 |
| `#[computed]`               | Field value is computed by an associated function. No declared computed-column dependencies.    |
| `#[computed(DEP1, DEP2)]`   | Same, but declares *other computed columns* this one reads. Required for cross-computed reads.  |
| `#[skip]`                   | Field is kept in the struct but no `Column` constant is generated and it is not tracked.        |

For every `#[computed]` field `foo`, the macro expects a method:

```rust
impl MyTable {
    fn foo(row: &Row<Self>, ctx: &Ctx) -> FooType { ... }
}
```

`row.get(Self::OTHER_COLUMN)` inside this function is what makes the engine track
the dependency — simply reading `row.other_column` directly would bypass tracking.
For cross-row or cross-table reads, use `ctx.lookup::<OtherTable>(&pk)` or
`ctx.lookup_index(&INDEX, &value)`.

### Field types and cloning

`Column<T, V>`'s getter is `fn(&T) -> V` — it must return an owned value. The derive
macro emits `.clone()` unconditionally, so:

- Prefer `Copy` types for primary keys and hot columns (`u64`, enums, `Pubkey`).
- Prefer `Arc<str>` over `String` for string columns (`Arc::clone` is a refcount
  bump; `String::clone` is a heap allocation).

### A fuller example

```rust
use hamondb::hamon_core::{Ctx, Row};
use hamondb::Table;

#[derive(Clone, Table)]
pub struct Category {
    #[primary_key]
    pub id: u64,
    pub markup_bps: u32,
}

#[derive(Clone, Table)]
pub struct Product {
    #[primary_key]
    pub sku: u64,

    #[index(CAT_ID_IDX)]
    pub category_id: u64,

    pub price_cents: u64,
    pub quantity: u32,

    #[computed(PRICE_CENTS, CATEGORY_ID)]
    pub effective_price_cents: u64,

    #[computed(QUANTITY)]
    pub needs_restock: bool,

    // Depends on another computed column — must be listed in the attribute.
    #[computed(NEEDS_RESTOCK, QUANTITY)]
    pub restock_urgency: u8,
}

impl Product {
    fn effective_price_cents(row: &Row<Self>, ctx: &Ctx) -> u64 {
        let price = row.get(Self::PRICE_CENTS);
        let cat_id = row.get(Self::CATEGORY_ID);
        let markup = ctx
            .lookup::<Category>(&cat_id)
            .map(|c| c.get(Category::MARKUP_BPS))
            .unwrap_or(0);
        price * (10_000 + markup as u64) / 10_000
    }

    fn needs_restock(row: &Row<Self>, _ctx: &Ctx) -> bool {
        row.get(Self::QUANTITY) < 10
    }

    fn restock_urgency(row: &Row<Self>, _ctx: &Ctx) -> u8 {
        if !row.get(Self::NEEDS_RESTOCK) { return 0; }
        let q = row.get(Self::QUANTITY);
        if q == 0 { 10 } else if q < 5 { 5 } else { 1 }
    }
}
```

The macro will arrange `#[computed]` columns in dependency order at build time and
panic (`computed column cycle detected: ...`) if they form a cycle.

## The CRUD API

All CRUD methods live on `Hamon` and return `Result<..., HamonError>`.

### `insert`

```rust
db.insert(Product { sku: 1, /* ... */ })?;
```

Errors with `HamonError::DuplicateKey` if the primary key already exists.

### `upsert`

```rust
db.upsert(Product { sku: 1, /* ... */ })?;
```

Insert if absent, replace if present. Handles the insert/delete race without an
internal retry loop — if a concurrent delete wins, you get
`HamonError::ConcurrentModification` and the caller decides what to do.

### `get`

```rust
let p: Product = db.get::<Product>(&42)?;
```

Returns a clone of the row. The clone is a snapshot — by the time your code reads
it, the row may have changed.

### `replace`

```rust
db.replace(Product { sku: 42, /* ... all fields ... */ })?;
```

Overwrites an existing row. Errors with `HamonError::KeyNotFound` if the row is
gone. Prefer `update` for partial changes — `replace` requires you to supply the
full row and it will diff columns internally to decide what cascades.

### `update`

```rust
db.update::<Product>(&42, (Product::QUANTITY, 7u32))?;
```

Partial update via a `(Column, value)` tuple. The engine:

- rejects updates to the primary key (`HamonError::PKColumnUpdate`),
- rejects updates to a computed column (`HamonError::ComputedColumnUpdate`),
- otherwise applies the change, recomputes any dependent computed columns, and
  cascades through dependents in other rows/tables asynchronously.

### `delete`

```rust
db.delete::<Product>(&42)?;
```

Removes the row and enqueues recomputation of anything that depended on it.

### Bulk reads

```rust
let n = db.len::<Product>();

db.for_each::<Product>(|row: &Product| {
    println!("{} → {}", row.sku, row.quantity);
});
```

`for_each` streams rows without materialising a `Vec` — zero allocation, no OOM
risk on large tables, but the closure must be fast (don't do I/O inside).

> **Design note.** `for_each` is an escape hatch, not a primary API. If you find
> yourself using it repeatedly to maintain an external index or computed value,
> that logic belongs inside `hamondb` as a secondary index, computed column, or
> listener instead.

## Indexes

Declare with `#[index(NAME)]` and look up with `db.lookup_index::<T, V>(T::NAME, &value)`:

```rust
#[derive(Clone, Table)]
struct Order {
    #[primary_key]
    id: u64,
    #[index(BY_SKU)]
    product_sku: u64,
    qty: u32,
}

let orders: Vec<Order> = db.lookup_index::<Order, u64>(Order::BY_SKU, &42);
```

Indexes are updated on every insert, replace, update, and delete that touches a
column the index depends on.

## Computed columns

See the fuller example above. The rules:

- The function signature is `fn <field>(row: &Row<Self>, ctx: &Ctx) -> <FieldType>`.
- `row.get(Self::COLUMN)` — same-row dependency; the engine tracks the read.
- `ctx.lookup::<OtherTable>(&pk)` — cross-table dependency; same row-granular tracking.
- `ctx.lookup_index(&INDEX, &value)` — index-bucket dependency; a write that moves
  a row into/out of the bucket will trigger recomputation.
- `ctx.slot(SLOT_HANDLE)` / `ctx.resource(RESOURCE_HANDLE)` — slot reads are tracked;
  resource reads are *not* (resources are explicitly non-reactive).
- A `#[computed]` field that reads *another* `#[computed]` field on the same row
  **must** list that field in `#[computed(...)]`. Reading an undeclared computed
  column panics with a message telling you which attribute to update. Self-reads
  also panic.

Cascades are deduplicated and run on a small internal thread pool.

## Slots

A slot is a typed singleton. It behaves like a 1-row table, so computed columns
can depend on it and be recomputed when it changes.

```rust
use hamondb_macro::slot;

slot!(pub CURRENT_EPOCH: u64);

// in build:
builder.register_slot(CURRENT_EPOCH, 0);

// at runtime:
let e: u64 = db.slot(CURRENT_EPOCH);
db.set_slot(CURRENT_EPOCH, 42).unwrap();
```

Inside a computed column: `ctx.slot(CURRENT_EPOCH)` — this *is* tracked, so bumping
the slot recomputes every dependent.

## Resources

A resource is an `Arc<V>` behind an `ArcSwap` — read-mostly configuration that can
be swapped atomically but is **not** reactive.

```rust
use std::sync::Arc;
use hamondb_macro::resource;

resource!(pub CURRENCY_LABEL: Arc<str>);

// in build:
builder.register_resource(CURRENCY_LABEL, Arc::<str>::from("USD"));

// at runtime:
let label: Arc<Arc<str>> = db.resource(CURRENCY_LABEL);
db.set_resource(CURRENCY_LABEL, Arc::<str>::from("EUR"));
```

Reading a resource inside a computed column does *not* register a dependency — swap
a resource and existing computed values will not be refreshed. Use a slot if you
need reactivity.

## Listeners

Register one or more callbacks per table, fired after every insert, replace,
update, or delete:

```rust
builder
    .register_table::<Product>()
    .register_listener::<Product>(|pk, old, new| {
        match (old, new) {
            (None, Some(row))         => println!("inserted {pk}: qty={}", row.quantity),
            (Some(old), Some(new))    => println!("updated  {pk}: {} → {}", old.quantity, new.quantity),
            (Some(_), None)           => println!("deleted  {pk}"),
            (None, None)              => unreachable!(),
        }
    });
```

Listeners run on the writer's thread, synchronously, after the write has been
committed. A listener panic is caught and logged — it will not take down the
writer.

## Feeders

A *feeder* is an owned worker thread that holds a `Hamon` handle and runs until
shutdown is requested. Useful for ingest loops, timers, or gRPC subscribers.

```rust
use std::time::Duration;

builder.register_feeder("tick".to_string(), |db, shutdown| {
    while !shutdown.is_triggered() {
        db.set_slot(CURRENT_EPOCH, now_epoch()).ok();
        if shutdown.wait_timeout(Duration::from_secs(1)) { break; }
    }
});
```

If a feeder panics, the process aborts (the engine does not try to resume with a
half-dead ingester).

## Shutdown

`build()` returns `(Hamon, HamonShutdown)`. Dropping the `HamonShutdown` triggers
the shutdown token and joins every feeder thread:

```rust
let (db, shutdown) = builder.build();
// ... use db ...
drop(shutdown); // or just let it go out of scope
```

Clone `Hamon` cheaply (it is `Arc`-backed internally) — the shutdown handle,
not `Hamon`, controls lifetime.

## Manual (no-derive) usage

Everything the derive macro does can be written by hand. This is useful when a
field is not directly a column (e.g. you want a custom getter) or in code that
cannot use procedural macros:

```rust
use hamondb::{Column, ComputedColumn, HamonBuilder, Index, Table};
use hamondb::hamon_core::{Ctx, Row};
use std::collections::HashSet;

#[derive(Clone)]
struct Simple {
    id: u64,
    val: String,
    three_val: String,
}

impl Table for Simple {
    type PrimaryKey = u64;
}

const COL_ID:        Column<Simple, u64>    = Column { id: 0, name: "Simple::ID",        get: |r| r.id,                set: |r, v| r.id = v };
const COL_VAL:       Column<Simple, String> = Column { id: 1, name: "Simple::VAL",       get: |r| r.val.clone(),       set: |r, v| r.val = v };
const COL_THREE_VAL: Column<Simple, String> = Column { id: 2, name: "Simple::THREE_VAL", get: |r| r.three_val.clone(), set: |r, v| r.three_val = v };
const VAL_IDX:       Index<Simple, String>  = Index::new(&[COL_VAL.id], 0);

impl Simple {
    fn three_val(row: &Row<Self>, _ctx: &Ctx) -> String {
        row.get(COL_VAL) + "foobar"
    }
}

let mut builder = HamonBuilder::new();
{
    let mut t = builder.register::<Simple, _>(COL_ID);
    t.register_regular_column(COL_VAL);
    t.register_index(VAL_IDX, |r| r.val.clone());
    t.register_computed_column(ComputedColumn {
        column: COL_THREE_VAL,
        closure: Box::new(Simple::three_val),
        computed_column_dependencies: HashSet::new(),
    });
    t.done();
}
let (db, _shutdown) = builder.build();
```

`Column` `id`s must be unique within a table; the derive macro uses the field's
index in the struct, which is stable as long as field order doesn't change.

## Concurrency model

- `get` returns a clone of the row — a snapshot. It may already be stale by the
  time your code reads it.
- Computed-column cascades across rows are dispatched to an internal worker pool
  via a deduplicated FIFO. Listeners for the row that triggered the write fire
  synchronously on the writer's thread; downstream listeners fire on a worker.
- Listener panics are caught per listener and logged. Feeder panics abort the
  process.

## What is NOT yet implemented

- **`Hamon::select` / a full query API** — only `for_each`, `lookup_index`, and
  point `get` exist today.
- **`#[indexed]` / `#[computed]` attribute validation by the macro** is partial
  — some invalid combinations are still rejected at `build()` rather than at
  compile time.
- **Stable crate on crates.io** — publishing is planned, versions are not yet
  pinned.
